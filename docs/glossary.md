# Glossary

## Security and Compliance Terms

| Term | Definition |
|------|------------|
| **Access Control** | The practice of restricting access to resources based on user identity and role |
| **Audit** | A systematic examination of records and activities to assess compliance and effectiveness |
| **Breach** | An incident resulting in unauthorized access to or disclosure of protected data |
| **Chain of Custody** | Documentation of the seizure, custody, control, transfer, and disposition of evidence |
| **CIA Triad** | Confidentiality, Integrity, Availability - the three pillars of information security |
| **Compensating Control** | An alternative control that satisfies a security requirement when the primary control is not feasible |
| **Compliance** | Conformance with laws, regulations, standards, and organizational policies |
| **Control** | A safeguard or countermeasure to prevent, detect, or correct security issues |
| **CVSS** | Common Vulnerability Scoring System - a framework for rating vulnerability severity |
| **Data Classification** | The process of categorizing data based on sensitivity and handling requirements |
| **DAST** | Dynamic Application Security Testing - testing running applications for vulnerabilities |
| **Evidence** | Documentation or artifacts that demonstrate control implementation and effectiveness |
| **GRC** | Governance, Risk, and Compliance - the framework for managing security governance |
| **HSM** | Hardware Security Module - a physical device for secure key management |
| **Incident** | A security event that compromises or threatens the confidentiality, integrity, or availability of systems |
| **Least Privilege** | The principle of granting only the minimum access necessary to perform a function |
| **MFA** | Multi-Factor Authentication - requiring two or more verification methods |
| **PII** | Personally Identifiable Information - data that can identify an individual |
| **PHI** | Protected Health Information - health data protected under HIPAA |
| **RBAC** | Role-Based Access Control - access decisions based on organizational roles |
| **Risk Acceptance** | A formal decision to accept a known risk without additional remediation |
| **Risk Register** | A document tracking identified risks, their assessment, and mitigation status |
| **SAST** | Static Application Security Testing - analyzing source code for vulnerabilities |
| **SIEM** | Security Information and Event Management - centralized log collection and analysis |
| **SLA** | Service Level Agreement - a commitment to a level of service (e.g., response time) |
| **SOC 2** | Service Organization Control 2 - a framework for managing customer data |
| **Tabletop Exercise** | A discussion-based simulation of a security incident for training and validation |
| **Threat Model** | A structured analysis of potential threats and their impact on a system |
| **TLS** | Transport Layer Security - a protocol for encrypting data in transit |
| **Vulnerability** | A weakness in a system that could be exploited to compromise security |
| **WAF** | Web Application Firewall - a filter for web traffic to protect against attacks |
| **Zero Trust** | A security model that requires strict verification for every access request |

## Organizational Roles

| Role | Responsibility |
|------|----------------|
| **CISO** | Chief Information Security Officer - executive responsible for security strategy |
| **Compliance Officer** | Manages compliance programs and audit readiness |
| **IR Team** | Incident Response Team - handles security incident detection and response |
| **Security Lead** | Technical lead responsible for security policies and controls |
| **System Owner** | Person accountable for a specific system's operation and security |
